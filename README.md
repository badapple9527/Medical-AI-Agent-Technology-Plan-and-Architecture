# 医疗智能体项目文档中心

> 工作代号：**MedEvidence Copilot**  
> 项目定位：面向复杂肿瘤病例的**循证临床决策支持系统（Clinical Decision Support System, CDSS）**。  
> 边界：系统输出供具备资质的临床医生审阅和决策使用，**不替代医生诊断、处方或治疗决策**。

---

## 1. 文档目标

本目录基于以下两类材料整理：

1. 参考文章《250名三甲医生输给中国AI！引发中美医疗权威热议》中描述的 MCE / MedGPT 类系统方案；

文章中的具体试验数字、模型版本和结论应视为**二手材料中的方案线索**，本规划不把其直接作为临床有效性证据。

**P0 前置准入动作：** 正式立项前必须完成原始论文/研究报告复核，包括研究设计、入组标准、评分规则、盲法、统计方法、伦理审批、利益冲突和可复现性。未完成该复核，不得把文章的 85 分、88:12 等数字写进立项材料的“有效性证明”部分。

---

## 2. 核心结论

这个项目不应被定义成“训练一个更大的医疗模型”，而应被定义成：

> **一个以结构化证据库为地基、以动态患者状态为输入、以多专科 Agent 编排和对抗式审查为流程、以可追溯决策报告为输出、以真实结局反馈为闭环的临床决策支持系统。**

系统由三条主线组成：

```text
知识生产线：文献/指南/说明书 → 证据单元 → 结论 → 证据包
患者数据线：病历/检查/病理/基因 → 临床事件 → 患者状态快照
临床决策线：患者状态 + 证据包 → 多专科意见 → 路径 → 审查 → 报告
```

## 4. 关键技术决策

1. **PostgreSQL 作为结构化事实源**：证据、结论、患者状态、版本、权限和审计以 PostgreSQL 为准。
2. **对象存储保存原始文件**：PDF、HTML、图片和快照放 MinIO/S3，数据库存对象地址和 hash。
3. **OpenSearch 做全文检索**：负责中文关键词、药名、基因名、指南术语、过滤、排序和高亮。
4. **向量检索做语义召回**：MVP 用 pgvector；规模和并发达到瓶颈后再引入 Milvus。
5. **证据原子化**：一条证据只表达一个主结论，绑定原文 span 和适用条件。
6. **证据包不是新证据**：证据包是针对一个 Claim 组织起来的证据集合，单条证据始终独立、可追溯。
7. **模型可替换**：所有模型通过统一 Model Gateway 接入，模型、提示词、embedding 和索引版本全部记录。
8. **安全规则不依赖 LLM**：禁忌、剂量、相互作用等硬约束由确定性规则引擎兜底。
9. **人机协同**：医生审阅、修改、签字，系统全程留痕。
10. **失败关闭**：证据不足、审查不通过或关键安全规则不满足时，系统应拒绝给出推荐，而不是编造答案。

## 6. 版本与历史报告约束

1. 证据库、Claim、EvidenceBundle、规则、模型和提示词都按版本管理；
2. **历史报告是不可变快照**；
3. 知识库更新不会自动改写历史报告；
4. 医生必须重新发起 `decision_run` 才能生成基于新证据的新版报告；
5. 若来源文献撤稿，历史报告保留原内容，但必须增加“所引证据已撤稿/失效”的显著提示；
6. 任何 `critical` 安全规则命中必须阻断推荐，LLM 审查意见不得覆盖硬规则。

## 7. 管理层风险摘要

管理层至少需要关注以下六类风险：

| 风险 | 说明 |
|---|---|
| 临床安全 | 证据适用性错误、禁忌遗漏、模型过度自信 |
| 数据与版权 | 文献授权、患者隐私、数据使用协议 |
| 临床采纳 | 医生不信任、报告过长、工作流不匹配 |
| 合规监管 | 医疗器械属性、注册路径、责任边界 |
| 成本 | 专家标注、知识库持续更新、医院集成、模型推理 |
| 供应商锁定 | 模型、向量库、检索组件和云服务绑定 |

## 9. 重要声明

本项目涉及医疗决策、患者隐私和医疗器械监管。任何上线、临床试用或对外宣传前，必须完成：

- 临床专家评审；
- 伦理与数据使用审批；
- 医疗器械属性判定与注册路径评估；
- 网络安全等级保护/数据安全评估；
- 医疗责任边界和保险方案确认；
- 前瞻性或影子模式临床验证。

本文档不构成法律、监管或临床建议。
